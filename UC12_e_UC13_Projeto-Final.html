Projeto final — seu sistema, do zero

Um sistema web com cadastro, login e área protegida. Individual, com tema de sua escolha, usando HTML, CSS, PHP e MySQL — exatamente o que estudamos nas aulas 1 a 7.

Individual Tema livre 11 arquivos 1 tabela (2 como diferencial) Entrega: data

1O que é este projeto

Você vai construir, do zero, um sistema pequeno e completo: uma tela de login, uma área que só abre para quem entrou, e um cadastro com as quatro operações — listar, cadastrar, editar e inativar.

É o mesmo desenho da aula 7, com uma diferença que é o ponto da atividade: lá o tema era produtos e o código estava pronto na tela. Aqui o tema é seu, e o código sai da sua cabeça.

Pode consultar a aula 7? Pode. Pode copiar e colar? Não. Abra os arquivos antigos quantas vezes precisar para lembrar como era — e depois escreva os seus, do começo, com os seus nomes de tabela e de campo. Projeto que é a aula 7 com as palavras trocadas é fácil de reconhecer, e não mostra o que você aprendeu.
Por que do zero Copiar um CRUD pronto leva vinte minutos e não ensina nada. Escrever um leva algumas horas e revela exatamente onde o entendimento está frouxo — que é justamente o que você quer descobrir agora, e não na primeira entrevista de emprego.

Qualquer coisa que se cadastre, se liste e se edite. Escolha algo que você entenda sem precisar pesquisar — o trabalho aqui é programar, não estudar o assunto.

São sugestões. Pode ser outro — só não vale prontuário, paciente ou leito, porque esse sistema já existe pronto e o exercício perde a graça.

A regra da escolha

Qualquer que seja o tema, a sua tabela principal precisa ter pelo menos cinco campos, e entre eles:

1
Um texto curto
Nome, título, descrição. É o campo pelo qual a listagem vai ser ordenada e buscada.
2
Um número
Preço, quantidade, nota, peso. Escolha entre inteiro e decimal com atenção — e saiba dizer por quê.
3
Uma data
Validade, agendamento, data de cadastro. Datas são onde mais se erra, e por isso entram.
4
Uma escolha de uma lista curta
Situação, categoria, tamanho, tipo. Vira um <select> na tela — e o valor dele é conferido no PHP antes de gravar, porque tudo que vem do navegador pode ter sido trocado.
5
A coluna ativo
TINYINT(1), valor padrão 1. É ela que faz o "inativar" funcionar sem apagar nada.

4O banco

Duas tabelas no mínimo: a de usuários, para o login, e a sua, do tema que escolheu.

CREATE TABLE usuarios (
    id     INT AUTO_INCREMENT PRIMARY KEY,
    nome   VARCHAR(100) NOT NULL,
    login  VARCHAR(50)  NOT NULL UNIQUE,
    senha  VARCHAR(255) NOT NULL,
    ativo  TINYINT(1)   NOT NULL DEFAULT 1
);
1
A senha tem 255 caracteres, e não 20
Porque o que vai ali não é a senha: é o hash dela, gerado pelo password_hash(). Hash não tem volta — não existe "descriptografar", só comparar com password_verify(). Senha guardada em texto puro é erro grave, e conta como erro na avaliação.
2
O script cria a tabela E põe três linhas de exemplo
Sem dados, a listagem abre vazia e você não sabe se ela funciona. Ponha três linhas no próprio .sql.
3
Comece o arquivo com SET NAMES utf8mb4;
Sem essa linha, dependendo de como o arquivo for carregado, os acentos entram trocados: "pão" vira "p├úo". Nada dá erro — só fica errado, em todas as linhas com acento, e ninguém percebe até a tela mostrar.
Como criar o primeiro usuário. Você não tem tela de cadastro de usuário — e não precisa ter. Rode uma vez, num arquivo PHP solto, echo password_hash('123456', PASSWORD_DEFAULT);, copie o resultado e cole dentro de um INSERT no seu .sql. Depois apague o arquivo solto.

5Os requisitos obrigatórios

Isto é a lista de conferência da avaliação. Passe por ela antes de entregar.

As quatro operações

1
Listar
Uma tabela na tela com os registros ativos, ordenada por nome. Inativo aparece apagado no fim da lista, ou não aparece — escolha e seja coerente.
2
Cadastrar
Formulário em branco, INSERT ao salvar, e volta para a lista.
3
Editar
O mesmo arquivo do cadastrar, com os campos preenchidos. Quem decide entre INSERT e UPDATE é o id: veio id, é UPDATE; não veio, é INSERT.
4
Inativar
UPDATE ... SET ativo = 0. Não existe DELETE neste projeto. O registro some da lista mas continua no banco — é assim que sistema de verdade faz, porque dado apagado não volta e quase sempre alguém depende dele.

As regras que valem em todas as telas

5
Toda consulta que recebe algo de fora usa prepared statement
Os quatro passos: mysqli_prepare · bind_param · execute · get_result. "De fora" é tudo que veio de $_POST, $_GET ou do formulário. É o que impede a injeção de SQL.
6
O formulário valida antes de gravar
Campo obrigatório vazio não entra. E a mensagem de erro aparece no campo errado, não num alerta genérico no topo.
7
O valor do <select> é conferido no PHP
A lista fechada na tela não garante nada: o navegador pode mandar qualquer coisa. Confira contra a sua lista antes de gravar.
8
Todo arquivo que só tem PHP termina sem a marca de fechar
Sem ?> no fim. Um espaço ou uma linha em branco depois dela vai para o navegador e quebra todo header('Location: ...'), com o erro "headers already sent".

6O login e a tranca — a parte que diferencia

CRUD sem login é exercício. CRUD com área protegida é sistema. É aqui que este projeto deixa de ser uma lista na tela.

Entrar

1
A senha é conferida com password_verify()
Nunca com =. O banco guarda o hash; password_verify() compara a senha digitada com ele.
2
A consulta do login filtra ativo = 1
Sem isso, desativar um usuário não desativa nada.
3
A mensagem de erro é a mesma nos dois casos
"Login ou senha incorretos", tanto para usuário que não existe quanto para senha errada. Se a tela disser "usuário não encontrado", ela está contando quais logins existem para quem estiver testando.

A tranca

Um arquivo só, protege.php, incluído na primeira linha de toda tela interna:

if (session_status() === PHP_SESSION_NONE) {
    session_start();
}

if (!isset($_SESSION['usuario_id'])) {
    header('Location: index.php');
    exit;
}
4
Em TODAS as telas internas, inclusive as que gravam
O X_salvar.php e o X_inativar.php também. É neles que o estrago aconteceria — a tela só mostra; quem grava é o arquivo de trás.
5
O exit depois do header não é enfeite
Sem ele o PHP continua executando o resto do arquivo. O navegador é desviado, mas o código já rodou — e se havia um INSERT ali, ele aconteceu.
Teste que você tem que fazer

Digite o endereço de uma tela interna sem estar logado

Abra X_listar.php direto na barra do navegador, sem passar pelo login. Se a tela aparecer, a tranca não está funcionando — e esconder o link do menu não resolve, porque o endereço continua lá. Esconder não é segurança. Faça esse teste antes de entregar.

7Atenção: a sintaxe mudou

Nas aulas 3 a 7 usamos a forma com seta — $conexao->prepare(). Neste projeto use a forma procedural, com mysqli_ na frente. É a mesma coisa escrita de outro jeito, e é a que o sistema do curso usa.

Nas aulas (não use aqui)Neste projeto
$conexao = new mysqli(...)$conexao = mysqli_connect(...)
$conexao->prepare($sql)mysqli_prepare($conexao, $sql)
$stmt->bind_param("si", ...)mysqli_stmt_bind_param($stmt, "si", ...)
$stmt->execute()mysqli_stmt_execute($stmt)
$stmt->get_result()mysqli_stmt_get_result($stmt)
$resultado->fetch_assoc()mysqli_fetch_assoc($resultado)
$stmt->close()mysqli_stmt_close($stmt)

Não misture as duas no mesmo projeto. Misturar funciona, e é exatamente por isso que é ruim: ninguém percebe, e o código passa a ter duas personalidades.

Vale saber As duas formas chamam o mesmo código por baixo — a diferença é só de escrita. A forma procedural combina com programação estruturada, que é a disciplina que vocês estão cursando. A forma com seta vocês vão reencontrar em orientação a objetos, mais adiante no curso.
A conta que o PHP não confere para você

Três contagens têm que ser iguais, não duas

Interrogações na consulta = letras no bind_param = variáveis passadas. "ssi" com três ? e três variáveis. Se uma das três não bater, o erro só aparece na hora de gravar — e a mensagem não diz qual das três está errada.

8O que NÃO precisa ter

Esta lista é tão importante quanto a dos requisitos. Nada aqui conta ponto, e tentar fazer tudo é a forma mais comum de não entregar.

  • Perfis de usuário. Logado ou não logado, só isso. Nada de administrador, gerente e visitante.
  • Cadastro de usuário pela tela. O usuário nasce no .sql.
  • Recuperação de senha. Nem "esqueci minha senha", nem e-mail.
  • Upload de imagem. Se o seu tema pede foto, guarde o endereço de uma imagem da internet num campo de texto.
  • Relatório, gráfico ou exportação. Nada de PDF, Excel ou gráfico.
  • JavaScript. Se usar, que seja enfeite. Nenhuma regra do sistema pode depender dele.
  • Mais de duas tabelas suas. Uma basta; duas é o diferencial. Três começa a ser outro projeto.
Um sistema pequeno e inteiro vale mais que um grande pela metade. Faça as quatro operações funcionarem de ponta a ponta primeiro. Só depois, se sobrar tempo, vá para os diferenciais.

9Diferenciais

Depois que o básico estiver funcionando. Cada um destes aparece na avaliação — e nenhum deles compensa um CRUD que não funciona.

1
Busca por nome na listagem
Um campo e um botão Filtrar. E repare: busca é valor vindo de fora, então ela obriga o prepared statement.
2
Uma segunda tabela, ligada à primeira
Um catálogo — categorias, marcas, tipos — que vira o <select> do formulário, com chave estrangeira. A listagem usa JOIN para mostrar o nome em vez do número.
3
O vazio que explica
Lista vazia não diz só "nenhum registro". Diz "nenhum resultado para essa busca" se houve busca, e "nenhum cadastro ainda" se o banco está vazio. São situações diferentes, e dizer a frase errada manda a pessoa procurar defeito onde não há.
4
Confirmação antes de inativar
Um confirm() ou uma tela de confirmação. Ação que muda dados não acontece com um clique distraído.
5
O nome de quem está logado na tela
No topo, com o botão Sair ao lado. Vem da sessão, que você já criou no login.
6
A tela funciona no celular
Abra o seu sistema no telefone, ou estreite a janela do navegador. Se a tabela estourar para o lado, resolva.

O que zera o item

Três coisas derrubam a nota do item inteiro

Senha guardada em texto puro · consulta montada com "... WHERE nome = '$nome'" em vez de prepared statement · tela interna que abre sem login. Não é rigor por rigor: são os três erros que, num sistema de verdade, têm consequência fora do computador.
